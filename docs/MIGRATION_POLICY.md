# Migration policy

Alembic is the sole schema authority for normal development, shared, and production-like environments. Application and worker startup never create tables. `Base.metadata.create_all()` is limited to isolated test fixtures and is not migration verification.

Released migrations are immutable. Before shared deployment, the original unreleased `0001_foundation` migration was corrected because it depended on current ORM metadata; it now contains an explicit schema snapshot. This correction is recorded in the Milestone 1.1 findings and report.

Create a new migration with `alembic revision --autogenerate -m "description"`, then inspect every generated operation: enums, defaults, data changes, constraints, indexes, and downgrade behavior require human review. Never accept autogenerated output blindly.

Run `alembic upgrade head`, `alembic downgrade base`, and `alembic upgrade head` against a disposable database. Run `python scripts/schema_drift.py .tmp-schema.db` to compare an Alembic-created schema with ORM metadata. If drift occurs, stop and determine whether the model or database is authoritative; correct it with a new reviewed migration after release.
