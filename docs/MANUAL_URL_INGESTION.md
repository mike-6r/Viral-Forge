# Manual URL ingestion

`POST /api/v1/ingestion/url` accepts a URL, optional existing source ID, optional idempotency key, and optional submission notes. An omitted idempotency key is generated by the API. A replay returns the pre-existing job with HTTP 200.

For a new submission the service normalizes the URL, records an ingestion job before retrieval, applies source policy, detects exact duplicates, safely fetches HTML, extracts metadata, checks canonical duplicates, creates source provenance and content, and transitions the content from `DISCOVERED` through `IMPORTED` to `SOURCE_VERIFICATION_REQUIRED`. The job contains the resulting content ID and completes as `SUCCEEDED`.

Failed requests cannot leave a content item behind: content-domain writes are rolled back while the pre-recorded job is retained as `FAILED` or bounded `RETRY_SCHEDULED`. Stable errors include SSRF blocking, unsupported type, response size, redirects, DNS/network, and remote-service categories. Audit events record successes, duplicates, and failures without remote response bodies or secrets.

The response includes job/status, content ID when present, normalized submitted URL, final URL, selected metadata, lifecycle state, warnings, and correlation ID. Public accessibility does not establish rights. Metadata retrieval does not authorize reuse and rights are never inferred from a public URL.
